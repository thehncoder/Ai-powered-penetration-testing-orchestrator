STRIDECategory.SPOOFING HIGH Authentication Token Forgery & Identity Spoofing

Adversaries may forge or tamper with authentication bearer tokens or session cookies to impersonate legitimate users.

Surfaces: http://MRHN.IN/login
Mitigation: Enforce cryptographically strong asymmetric signatures (RS256/Ed25519) on all JWTs, strictly forbid 'none' algorithm, and rotate signing keys periodically.
STRIDECategory.TAMPERING HIGH Input Parameter Manipulation & Query Tampering

Unsanitized query parameters or request bodies could allow adversaries to tamper with database queries or application state.

Surfaces: http://MRHN.IN/api/users, http://MRHN.IN/api/user/profile, http://MRHN.IN/api/search
Mitigation: Enforce strict Pydantic/JSON schema validation on all inputs; utilize parameterized ORM queries; apply cryptographic HMACs for stateful parameters.
STRIDECategory.REPUDIATION MEDIUM Insufficient Transaction Audit Logging & Non-Repudiation Deficit

State-altering API calls may lack tamper-evident forensic logging, allowing malicious actors to deny performing actions.

Surfaces: http://MRHN.IN/login, http://MRHN.IN/api/user/profile, http://MRHN.IN/api/view
Mitigation: Implement append-only, cryptographically hashed audit trails for sensitive operations capturing timestamp, user ID, client IP, and request digest.
STRIDECategory.INFORMATION_DISCLOSURE MEDIUM Technology Stack Fingerprinting & Verbose Error Leakage

Server response headers, stack traces, and unauthenticated metadata endpoints disclose underlying framework and runtime versions.

Surfaces: mrhn.in
Mitigation: Strip 'Server' and 'X-Powered-By' headers in reverse proxy configs; disable detailed exception stack dumps in production environments.
STRIDECategory.DENIAL_OF_SERVICE HIGH Unthrottled API Resource Exhaustion & Heavy Query DoS

Lack of explicit rate-limiting tokens allows concurrent high-frequency queries to exhaust backend threads and database connection pools.

Surfaces: http://MRHN.IN/api, http://MRHN.IN/api/v1, http://MRHN.IN/openapi.json
Mitigation: Deploy leaky-bucket or token-bucket rate limiting (e.g. Redis sliding window) at the API gateway layer.
STRIDECategory.ELEVATION_OF_PRIVILEGE CRITICAL Horizontal & Vertical Role Authorization Bypass

Administrative endpoints or object identifiers may not consistently enforce server-side Role-Based Access Control (RBAC).

Surfaces: http://MRHN.IN/admin, http://MRHN.IN/api/admin/config, http://MRHN.IN/dashboard
Mitigation: Adopt centralized authorization policy middleware; enforce Principle of Least Privilege across all route handlers.

CRITICAL 9.8 VULN-SQLI-127

SQL Injection in parameter 'id'

CWE-89
💡 Plain English Breakdown (Non-Technical Summary)

The website takes what you type in the search/input box and pastes it straight into the database query without checking it first. It's like asking a bank teller for your balance, but slipping in a fake note that commands the teller to hand over everyone's bank account numbers.

📍 Where is the Flaw: Endpoint 'GET http://MRHN.IN' at parameter 'id'. The backend uses string concatenation (e.g. query = 'SELECT ... ' + user_input) instead of parameterized queries.
💥 Business & User Impact: Mass Data Breach: Total unauthorized dump of customer passwords, confidential records, and potential remote control over the database server.
🏴‍☠️ How an Attacker Can Exploit This (Attack Scenario)
⚡1. Attacker sends a single quote (') to break the query syntax.
⚡2. Injects an unconditional SQL command (e.g. ' OR 1=1 --).
⚡3. Uses UNION SELECT or automated tools to dump entire database tables (users, passwords, credit cards).
