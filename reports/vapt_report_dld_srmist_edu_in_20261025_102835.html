CRITICAL 9.3 VULN-SSRF-001

Server-Side Request Forgery (SSRF) to Cloud Metadata

CWE-918
💡 Plain English Breakdown (Non-Technical Summary)

The web server acts as an obedient proxy for the attacker. If the attacker tells it to fetch an address, it will fetch it—even if that address is a secret internal cloud management server that normal internet users can't reach.

📍 Where is the Flaw: Endpoint 'GET https://dld.srmist.edu.in/api/fetch' at parameter 'url'. The server makes HTTP requests to user-supplied web addresses without restricting internal private IP spaces.
💥 Business & User Impact: Cloud Infrastructure Takeover: Exposure of cloud IAM keys, unauthorized access to private databases, and lateral movement across the entire virtual network.
🏴‍☠️ How an Attacker Can Exploit This (Attack Scenario)
⚡1. Attacker sets the 'url' parameter to 'http://169.254.169.254/latest/meta-data/'.
⚡2. The server queries the internal AWS/GCP instance metadata endpoint on behalf of the attacker.
⚡3. The response contains temporary IAM admin credentials, secret keys, and internal network IP lists.
🔬 Technical Forensics & Reproduction

The server accepts arbitrary external URLs and queries them from within the trusted backend network boundary.

Endpoint: GET https://dld.srmist.edu.in/api/fetch
Parameter: url
OWASP: A10:2021-Server-Side Request Forgery
CVSS 3.1: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:L/A:N
Evidence Hash: 08ab1a7ebd3ada4b

🧪 Verified Proof of Concept (cURL Reproduction)

curl -s -i -X GET 'https://dld.srmist.edu.in/api/fetch?url=http://169.254.169.254/latest/meta-data/'

🛠️ How to Fix (Remediation Guidance)

Implement strict URL allowlisting, block private IP address spaces, and enforce IMDSv2 token authentication.

# Secure Implementation (IP Range Validation):
import ipaddress
ip = ipaddress.ip_address(resolved_ip)
if ip.is_private or ip.is_loopback:
    raise SecurityException("Internal IP access denied")

CRITICAL 9.1 VULN-ADMIN-001

Unauthenticated Access to Administrative Endpoint: https://dld.srmist.edu.in/admin

CWE-306
💡 Plain English Breakdown (Non-Technical Summary)

The admin control panel has no lock on the front door. Anyone who knows or guesses the URL can enter and use management functions without entering any password or logging in.

📍 Where is the Flaw: Endpoint 'GET https://dld.srmist.edu.in/admin'. The route handler lacks authentication and role-based access control (RBAC) middleware, allowing open anonymous internet traffic to reach management functions.
💥 Business & User Impact: Full Administrative Compromise: Unauthorized management of users, backend configurations, system status, and internal operational data.
🏴‍☠️ How an Attacker Can Exploit This (Attack Scenario)
⚡1. Attacker discovers the admin endpoint via directory brute-forcing or automated scanning.
⚡2. Attacker sends a direct request without any authorization headers.
⚡3. The application grants unrestricted access to privileged operations, user lists, and internal system configs.
🔬 Technical Forensics & Reproduction

Privileged administrative endpoint is accessible anonymously without authentication or RBAC validation.

Endpoint: GET https://dld.srmist.edu.in/admin
Parameter: None
OWASP: A01:2021-Broken Access Control
CVSS 3.1: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N
Evidence Hash: ed70d7bcf123bb7e

🧪 Verified Proof of Concept (cURL Reproduction)

curl -s -i -X GET 'https://dld.srmist.edu.in/admin'

🛠️ How to Fix (Remediation Guidance)

Enforce role-based access control (RBAC) middleware on all administrative route groups.

# Secure Middleware:
@app.middleware("http")
async def require_admin_role(request: Request, call_next):
    if request.url.path.startswith("/admin") and request.state.user.role != "ADMIN":
        return Response(status_code=403)
    return await call_next(request)

MEDIUM 5.3 VULN-HDR-001

Missing Critical Security Hardening Headers: Content-Security-Policy (CSP), X-Content-Type-Options

CWE-16
💡 Plain English Breakdown (Non-Technical Summary)

The server is missing browser security shield instructions. These headers tell browsers not to allow other websites to frame your site inside an invisible window (clickjacking) or guess file types dangerously.

📍 Where is the Flaw: HTTP response headers on base URL 'https://dld.srmist.edu.in'. The web server configuration is missing defensive HTTP headers: Content-Security-Policy (CSP), X-Content-Type-Options.
💥 Business & User Impact: Clickjacking & MIME Spoofing: Users can be tricked into performing unintended state changes, or browsers can be tricked into executing malicious scripts via MIME confusion.
🏴‍☠️ How an Attacker Can Exploit This (Attack Scenario)
⚡1. Attacker embeds your website in an invisible iframe on a malicious webpage (Clickjacking).
⚡2. The attacker tricks a logged-in user into clicking buttons on the overlay, unknowingly performing transactions or altering account settings.
🔬 Technical Forensics & Reproduction

The application responds without critical security defenses (Content-Security-Policy (CSP), X-Content-Type-Options), increasing susceptibility to clickjacking and MIME-type sniffing.

Endpoint: GET https://dld.srmist.edu.in
Parameter: HTTP Response Headers
OWASP: A05:2021-Security Misconfiguration
CVSS 3.1: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N
Evidence Hash: ab279e9ef13c77d2

🧪 Verified Proof of Concept (cURL Reproduction)

curl -s -i -X GET 'https://dld.srmist.edu.in'

🛠️ How to Fix (Remediation Guidance)

Configure reverse proxy or web application middleware to return defensive security headers.

# Secure Nginx Configuration:
add_header X-Frame-Options "DENY" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Content-Security-Policy "default-src 'self';" always;
